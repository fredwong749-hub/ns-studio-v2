## 1. 验收（项目方定：一整集新剧本全自动出片）
1. 一集**新**剧本（12–16 镜，由 Claude 按 L-109 写）从剧本到成片**全自动**，中间 0 次人工派单
2. 墙钟 **≤ 50 分钟**（含重试；两台 5 道）
3. 项目方**只点一次**“全部通过”（成人镜触发除外，L-128 不变）
4. 质量门槛（基线 → 目标，基线在 R0 实测后填）：首帧一次过率 27% → **≥ 60%**；视频尽力版 44% → **≤ 10%**；成片时长与剧本差 ≤ 2 秒
5. 同输入 0 新版本；回滚演练通过；全部测试通过
6. 代码：运行时**不再 import 旧代码树**（services/、packages/、tools/），旧树只读存档

## 2. 设计要点
### 2.1 一份数据（解决复杂 + 交接 bug）
- gpu33 是唯一存储与队列；gpu36 是纯算力：领活时经文件口拉输入、跑完把产物推回 gpu33，本机不留权威副本
- takes（版本表）从各机 takes.json 搬进 queue.db 的 `takes` 表；**语义不变**：active / seq、trial 不动 active、只有真新材料才加版本（这是 P5 红线，只换存放位置，需项目方批，见 §4 决定 1）
- 交接模块 handoff.py 随之删除

### 2.2 去旧代码（解决复杂）
用 ns2 原生小模块替换 6 个旧依赖，每个先写对照测试（同输入新旧输出一致）再切：
- `ns2/comfy.py`：提交 / 等待 / 取消 / 上传（替 comfy_client）
- `ns2/frame_compile.py`：首 / 尾帧工作流编译（替 unified_frame + frame_job，按 shot_spec_v2 + camera_moves.yaml）
- `ns2/vqa.py`：质检契约（替 vqa.contract）
- `ns2/takes.py`：版本表（替 pipeline.mutate_takes）
- script / board 导入改原生（不再调旧 import_script）

### 2.3 快（KPI ≤ 50 分钟）
- **并行候选代替串行重试**：首帧一次出 2–3 个种子 / 构图档同时打分取最好，而不是不过再排队重来（同 GPU 批量，省排队与模型加载）
- **出图前构图预检**：分镜阶段先查“排排站”等已知坏构图，改写提示再出图（把重试挪到便宜的文字阶段）
- **调度**：关键路径优先（先出视频最长的镜的首尾帧）；视频在两台 5 道上按时长装箱
- 每集出耗时归因报告（逻辑 / 代码 / GPU 调度 / 检测，KPI 规则 L-205）

### 2.4 少管（默认通过）
- **默认通过**：过了质检的片自动定稿；项目方只在总览上挑例外点“修改”，或一键“全部通过”收尾（11-09 项目方规矩）
- **尽力版不再默认等人**：分数过“可用线”的自动用、低于线的自动换种子 / 构图再跑一轮，仍不过才列进“例外”
- 成人镜：剧本里标了的镜集中在一处列出，一次勾选触发（仍是项目方亲自触发，只是不再逐镜找）

### 2.5 质量
- 质检门校准：用 series10 已定稿的 54 镜做正样本、尽力版做负样本，调阈值并记录误判率
- 镜头语言硬规（虚化、机位一致、动机运镜、动作点剪辑）进编译器而不是靠重试碰
